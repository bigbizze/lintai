# lintai 0.4.0: strict reachability facts and rule integrity

You are working in a clone of `bigbizze/lintai`. This document is the full specification for release 0.4.0. It assumes release 0.3.0 has landed (`specs/extraction-vendored-tsgo.md`: the TypeScript 7 compiler copied into `internal/tsgo/internal/`, and the extractor in `internal/tsgo/lintaiapi/`, calling the parser and checker in-process). If it has not, implement the extraction items of section 3 in the fork's `lintaiapi` instead; the code is the same, only its location differs. Everything else is independent of extraction. Before writing code, copy this document into the repository as `specs/strict-facts-and-rule-integrity.md`.

Two problems, one release.

**Soundness.** `call_edge` exists only when the checker resolves a call to a collected declaration. So `const f = deps.fetchData; f()` silently passes through every transitive rule, and a dynamic import with a computed specifier produces no facts at all. 0.4.0 does not try to resolve these. It makes them visible as facts, so a rule can choose to fail closed, the same way `ambient_dynamic` already handles computed ambient keys.

**Trust.** Rule files are workspace code, `setup()` runs with full Node capabilities, and nothing detects a changed rule. 0.4.0 adds a rules lockfile and runs the setup phase in a sandbox.

Rule errors are already visible in the editor: since `504e6c0` the ESLint plugin reports rules that could not run on line 1 of linted files. Do not change that path.

New base relations and prelude predicates are additive and cannot break existing rules, because rules cannot declare base or prelude predicate names. The setup sandbox is a behavior change, specified below with its opt-out.

## 1. What changes

1. Three new base relations: `call_unresolved`, `import_opaque` and `fn_ref`, each with `location` facts and, where applicable, `site_in_fn` rows.
2. Prelude additions for strict reachability and package capabilities: `calls_or_refs_reach`, `fn_has_unresolved_call`, `module_has_unresolved_call`, `fn_reaches_unresolved`, `fn_reaches_ambient_strict`, `fn_calls_package` and `module_calls_package`.
3. A rules lockfile. `lintai lock` writes it, and `--rules-lock` enforces it before any rule's `setup()` runs. A mismatch is a rule error with the new phase `integrity` and the existing exit code 3.
4. The setup phase runs under Node's permission model (read-only filesystem scoped to the workspace, no child processes, no workers), with `require()` at run time limited to Node built-ins. It is on by default on Node 22.13 or later, with `--setup-sandbox=off` to opt out.
5. Documentation: a strict-mode example rule, a package-capability example, a new `docs/trust.md`, and README wording that states what is and is not guaranteed.

## 3. New base relations

Add them to `schema.mg`, extraction, `facts.go`, `docs/api.md` and the `lintai schema` output. Every new entity id gets a `location` row, and `call_unresolved` sites inside collected functions get `site_in_fn` rows. Exact declarations:

```
Decl call_unresolved(Site, Caller)
  descr [
    extensional(),
    doc("A call or new expression whose target the checker does not resolve to a collected workspace function or an external declaration. Callbacks, function-typed values, element-access callees, and any-typed callees produce this fact. Every call site has exactly one of: call_edge, external_call, call_unresolved."),
    arg(Site, "Call site entity id."),
    arg(Caller, "Entity id of the calling function, or the module path for a call at module scope.")
  ].

Decl import_opaque(Site, From)
  descr [
    extensional(),
    doc("A dynamic import() or require() whose specifier is not a string literal. These references have no import_edge row; this fact makes them visible."),
    arg(Site, "Reference site entity id."),
    arg(From, "Path of the file that contains the reference.")
  ].

Decl fn_ref(Ref, From, To)
  descr [
    extensional(),
    doc("A reference to a collected function as a value, outside the callee position of a call: passed as an argument, stored, returned, or used as a property value. Import and export specifiers are not references; import facts model them."),
    arg(Ref, "Reference entity id."),
    arg(From, "Entity id of the containing function, or the module path for a reference at module scope."),
    arg(To, "Entity id of the referenced function.")
  ].
```

Extraction semantics:

- **`call_unresolved`.** In call collection, the three outcomes cover every call: resolved to a collected workspace function gives `call_edge`; resolved to a declaration outside the workspace sources gives `external_call`; everything else gives `call_unresolved`. "Everything else" includes callees typed as function types without a resolvable declaration (parameters, properties of records of functions), `any` or `unknown` callees, element-access callees, and optional calls `f?.()`. Entity ids and semantic keys follow the existing call-site conventions. Files with parse errors keep today's behavior, where facts may be incomplete.
- **`import_opaque`.** Produced for `import(expr)` and `require(expr)` when the argument is not a plain string literal: template literals with substitutions, identifiers, concatenations. A template literal without substitutions counts as static and keeps producing a normal `import_edge`, matching current behavior. Check this against the golden facts and correct this sentence if the current extractor treats it differently.
- **`fn_ref`.** An identifier or property access whose symbol, after alias resolution, is a collected workspace function. It excludes the callee of a call expression that produced a `call_edge`, `external_call` or `call_unresolved` row, import and export specifiers, and the function's own declaration name. Each reference site is its own entity. `From` uses the same function-or-module convention as `call_edge`'s `Caller`.

## 4. Prelude additions

Append these to `prelude.mg`, matching its clause style (linear recursion, declared docs). They are reserved like every prelude predicate:

```
Decl calls_or_refs_reach(From, To)
  descr [
    doc("Transitive closure over call_edge and fn_ref together: a conservative over-approximation of workspace-internal reachability."),
    arg(From, "Function entity id, or module path for module-scope sites."),
    arg(To, "Function entity id reached through calls or function-value references.")
  ].
calls_or_refs_reach(A, B) :- call_edge(_, A, B).
calls_or_refs_reach(A, B) :- fn_ref(_, A, B).
calls_or_refs_reach(A, C) :- call_edge(_, A, B), calls_or_refs_reach(B, C).
calls_or_refs_reach(A, C) :- fn_ref(_, A, B), calls_or_refs_reach(B, C).

Decl fn_has_unresolved_call(Fn)
  descr [ doc("Fn directly contains a call the checker could not resolve."), arg(Fn, "Function entity id.") ].
fn_has_unresolved_call(Fn) :- call_unresolved(Site, _), site_in_fn(Site, Fn).

Decl module_has_unresolved_call(File)
  descr [ doc("File contains an unresolved call at any scope."), arg(File, "Path of the file.") ].
module_has_unresolved_call(File) :- call_unresolved(Site, _), location(Site, File, _, _, _, _).

Decl fn_reaches_unresolved(Fn)
  descr [ doc("Fn contains an unresolved call, directly or through calls_or_refs_reach. A strict rule treats this as leaving the analyzed code."), arg(Fn, "Function entity id.") ].
fn_reaches_unresolved(Fn) :- fn_has_unresolved_call(Fn).
fn_reaches_unresolved(Fn) :- calls_or_refs_reach(Fn, Callee), fn_has_unresolved_call(Callee).

Decl fn_reaches_ambient_strict(Fn, Source)
  descr [ doc("Like fn_reaches_ambient, but over calls_or_refs_reach."), arg(Fn, "Function entity id."), arg(Source, "Source name constant.") ].
fn_reaches_ambient_strict(Fn, Source) :- fn_uses_ambient(Fn, Source).
fn_reaches_ambient_strict(Fn, Source) :- calls_or_refs_reach(Fn, Callee), fn_uses_ambient(Callee, Source).

Decl fn_calls_package(Fn, Pkg)
  descr [ doc("Fn directly calls into a package. lib calls are excluded."), arg(Fn, "Function entity id."), arg(Pkg, "Package name from external_call.") ].
fn_calls_package(Fn, Pkg) :- external_call(Site, _, Pkg, _), site_in_fn(Site, Fn), Pkg != "lib".

Decl module_calls_package(File, Pkg)
  descr [ doc("File directly calls into a package, at any scope."), arg(File, "Path of the file."), arg(Pkg, "Package name from external_call.") ].
module_calls_package(File, Pkg) :- external_call(Site, _, Pkg, _), Pkg != "lib", location(Site, File, _, _, _, _).
```

None of these uses negation, so stratification is unaffected, and `preludeFor` pruning picks them up automatically.

A strict purity rule then reads: a violation when `glob(File, pure)` holds and the function has `fn_reaches_ambient_strict` for any source, or `fn_reaches_unresolved`. The package-capability pattern is a `.facts()` table `package_capability(Pkg, Source)` joined against `fn_calls_package`. Both go into `docs/examples.md` as worked examples with planted violations.

## 5. Rules lockfile

**Hash basis.** Run both esbuild builds in `bundle-rule.mjs` with `metafile: true`. For each rule, the hash input is the union of both metafiles' `inputs` as a sorted list of `(normalized path, sha256 of file bytes)` pairs. A path under the workspace root is workspace-relative. A path under any `node_modules` is cut to start at the package directory inside `node_modules`, so the hash does not depend on the machine or the install layout. The rule hash is the sha256 of the canonical JSON of that list. Bundler output bytes are not hashed, so an esbuild upgrade does not change the lock when no input changed. Return the per-rule hash and input list in the bundle response rows.

**Run-time code.** The lock covers only code the bundler sees. A `require()` with a computed argument inside `setup()` is left for run time, so it could load workspace code the lock never hashed. Section 6 closes this: during prepare, `require()` resolves only Node built-ins, and dynamic `import()` is unavailable. All workspace code a rule uses must therefore be imported statically, which puts it in the bundle and in the hash. Files that `setup()` reads as data through `fs` are not covered by the lock. `docs/trust.md` says so.

**File format.** `lintai-rules.lock.json` at the workspace root by default:

```json
{
  "version": 1,
  "rules": {
    "lintai-rules/no-service-imports.ts": { "hash": "sha256:..." }
  }
}
```

**Commands and flags.**

- `lintai lock`, a new subcommand. It takes the same `--workspace-root`, `--rules`, `--asset-root` and `--repo-root` flags as a run. It discovers and bundles the rules, writes the lockfile (path overridable with `--lock-file`), and prints one line per rule. Exit 0 on success, 2 on failure.
- `--rules-lock <path>` on one-shot runs, `rulesLock` in the serve `initialize` params and in the ESLint plugin options, and a field on `engine.Options` for Go consumers. When set, after `BuildAll` and **before** `PrepareAll`, so that a changed rule's `setup()` never runs, compare each discovered rule's recomputed hash with the lock. A mismatch, a discovered rule missing from the lock, or a locked rule that no longer exists each produce a `rule_execution_error` with the new phase `integrity` and a message naming the rule and the kind of mismatch. That rule is excluded from prepare and evaluation. The existing exit-code contract gives these runs exit 3.

## 6. Setup sandbox

`bundle.PrepareAll` currently spawns `node prepare-rule.mjs`. When the sandbox is active, spawn instead:

```
node --permission \
  --allow-fs-read=<workspaceRoot> --allow-fs-read=<bundle outDir> --allow-fs-read=<assetRoot> \
  <assetRoot>/scripts/prepare-rule.mjs
```

No `--allow-fs-write`, no `--allow-child-process`, no `--allow-worker`, and never `--allow-net`. On Node 25 and later this denies network access to `setup()`, which is intended. On Node 22.13 to 24 the permission model does not restrict the network at all. Record that in `docs/trust.md` as a gap that depends on the Node version, citing the Node CLI docs.

**Restricted require.** In `prepare-rule.mjs`, load the CommonJS prepare bundle by reading its source and running it as a CommonJS function (`vm.compileFunction` with parameters `exports, require, module, __filename, __dirname`), passing a `require` that returns a module only when `module.isBuiltin(name)` is true and otherwise throws an error naming the requested specifier and pointing at `docs/trust.md`. Do not pass an `importModuleDynamically` option, so a dynamic `import()` inside the bundle fails. Apply this whenever the sandbox is active, and also whenever `--rules-lock` is set, even with the sandbox off, because the lock depends on it.

**Activation.** A new flag `--setup-sandbox=auto|on|off` (default `auto`) on one-shot runs, a serve param, an ESLint plugin option `setupSandbox`, and a field on `engine.Options`.
- `auto`: check the Node version once per process (`node --version`). Sandbox when it is 22.13 or later. Otherwise run as before and print one warning line to stderr.
- `on`: fail with a clear usage error (exit 2) if the Node version cannot support it.
- `off`: the old behavior, with no warning.

**Error mapping.** An `ERR_ACCESS_DENIED` escaping a rule's `setup()`, and an error from the restricted `require`, must surface as that rule's `rule_execution_error` with phase `setup` and a message naming the denied permission or specifier and the resource, pointing at `--setup-sandbox=off` and `docs/trust.md`. Catch them per rule in `prepare-rule.mjs`. The existing per-payload try/catch already isolates rules; extend `formatError` to recognize these errors.

**Scope.** Only the prepare phase is sandboxed. Bundling reads rule files but runs no rule code, and esbuild itself needs child processes and writes, so sandboxing it does nothing against rule authors. The Goja pure phase already has no capabilities. Record this in the commit message and in `docs/trust.md`.

**Entrypoint reads.** Node 22.17 and later allow reading the entrypoint implicitly. Still pass `--allow-fs-read=<assetRoot>` so helper imports under `scripts/` resolve on every supported version.

## 8. Not goals

- No points-to or dataflow analysis. `fn_ref` and `call_unresolved` are a deliberate over-approximation and under-approximation pair, not a call-graph solver.
- No analysis inside `node_modules`. Package capabilities are tables the user supplies.
- No lockfile signing or key management. Integrity is content hashing plus repository process.
- No sandboxing of the bundling step, and no attempt to restrict the network on Node 22 to 24.
- No change to how rule errors reach the editor.
