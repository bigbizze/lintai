# LintAI implementation specification

## Purpose and branch

Build rules once, run them as pure programs in Go, and let each host declare when an analysis operation begins and ends. A whole-project lint invocation should compute or validate one result. An editor request should describe the saved source from which its findings were derived. The project owner accepts breaking changes to the SDK, CLI, Go API, lock, host configuration, and wire protocol to get this model.

## 1. Build a single file of executable rules

Add `lintai build-rules`. Configure the entry files with a `[rules]` section in workspace-root `lintai.toml`. Use a list of relative POSIX-style entry paths. For example, this project builds two entries and configures one of them.

```toml
[rules]
entries = ["lintai-rules/layers.ts", "lintai-rules/service-imports.ts"]

[rule."arch.pure-no-service-imports"]
severity = "warning"
options = { pureDir = "src/domain", serviceDir = "src/services" }
```

Entries identify actual rules. Helpers and static JSON data are dependencies reached by imports. Reject duplicate entries, absolute or escaping entry names and nonportable case collisions. Order entries by normalized name. Default the output to `.lintai/rules.json` under the workspace root. Reserve that path for the generated file. Exclude generated pack and temporary output from rule entry selection and default application source selection. An explicit empty list creates a valid empty pack. Distinguish empty, missing configuration, missing entry and missing pack in commands and errors.

Use one pinned esbuild configuration. Prefer the Go API so the distributed executable can build a project with its SDK and rule dependencies installed. Bundle each entry and its static dependencies as an independently evaluable program targeting the supported Goja runtime. Support the SDK, relative TS/JS modules, bundled pure packages, and static JSON imports. Reject unsupported runtime imports and unresolved dependencies during build. Fix the rule compiler's resolution conditions and TypeScript transform settings. Do not inherit workspace TS path aliases, plugins, ambient tsconfig discovery or ambient build environment. Analysis of the *application's* TypeScript still honors its configured compiler inputs. A rule or dependency with a construct that the pure target cannot execute must produce an actionable error.

The compiler detects unsupported import forms and build errors. A successfully bundled entry that throws at initialization or returns an invalid rule shape produces a named runtime diagnostic. A second build-time VM would duplicate inspection.

One deterministic UTF-8 JSON file contains a format identifier, a rule runtime ABI identifier, and the ordered entries. Each entry contains its logical source name and bundled JavaScript text. For example, an entry is shaped as `{"entry":"lintai-rules/layers.ts","code":"…"}`. The ABI defines how the engine obtains the default rule and optional configuration parser. Rule ID, version, assertions and suppression declarations are decoded by the engine from the executable. Avoid a second hand-maintained inventory of those values. Reject malformed envelopes, duplicate keys/entries, unsupported versions and invalid entry records before evaluation. Keep checkout paths, timestamps, random build IDs, source maps containing absolute paths, host-specific line endings, and platform executable fingerprints out of the output. Preserve string-literal semantics when building. Define one stable encoder and ordering.

Compilation reads rule sources and emits JavaScript without executing user rule code. Build all entries, then replace the pack with a completed temporary sibling. On failure or cancellation before commit, return failure and leave the last good file readable. Concurrent readers must see a complete old or complete new pack on supported platforms. Source changes take effect on a successful explicit build. A check reads the published file and never implicitly repairs it. A clean CI checkout runs the build before enforcement and stops if the build fails. A different source edit that emits identical bytes can keep its approval. Auditing source changes belongs to source review.

## 2. Authoring, execution and approval

Keep the SDK's rule ID, version, `.facts()`, `.program()`, `.report()`, `.expectNonEmpty()`, `.message()`, `.suppression()` and typed Datalog interpolation. Remove `.setup()`, its context and generic type parameter, the runtime setup output, Node preparation scripts, setup sandbox modes and related CLI/Go/host options. An entry that needs to validate configuration may export `config` with a synchronous `parse(value)` method. This lets existing pure Zod object schemas supply defaults and validation if they run in the target. Without a parser, use the configured JSON object. The parsed result must be JSON-shaped, finite and detached, then frozen before passing it as `env`. Reject asynchronous or unrepresentable results as rule configuration errors. Document this with a working packed example.

Policy lists maintained with a rule can be static imports, for example `import layers from "./layers.json"` and `.facts(() => ({ layer_glob: layers.rows }))` for rows of strings. Changes to them require a rebuild. Live project data comes from an existing fact producer with explicit inputs, scope, revision and validity. A producer unable to prove reuse from observations must cause a fresh preparation on the next operation. Port existing examples by intent. This specification introduces no general file-reading callback, arbitrary preparation hook or new data-provider interface.

Run each eligible rule's initialization, configuration parsing, facts, program and messages under the existing pure-runtime restrictions. No ambient process, filesystem, network, wall-clock time, randomness or Node module loader. Retain one fresh VM for an actual execution, share it within that execution, and release it at completion. A metadata-only inventory or lock inspection drops each VM after decoding its detached metadata. Disabled rules still participate in ID and configuration-name validation. Skip their execution callbacks. An invalid rule produces its ordered rule diagnostic while unrelated valid entries in an otherwise accepted pack can run. Treat a duplicate ID as a problem for every conflicting entry. Preserve meaningful diagnostic ordering and wording for surviving failure categories. Replace references to removed setup/sandbox phases in messages and examples.

Use one new lock format. In locked mode the trust input is the exact pack byte sequence used by this operation. Hash it once, compare the full pack digest and supported ABI against the approved lock, and execute only entries decoded from the same owned bytes. The digest covers additions, removals, code and entry names together. Check the applicable approved policy before initializing *any* rule. An invalid or mismatched pack or lock fails the operation with an integrity diagnostic and the established nonzero integrity exit status. Keep suppression declarations separate from approved allowances, groups, counts and reasons. Allow removal and tightening within the approved ceiling. Broadening a group, count or reason beyond approval requires renewed approval. Preserve recording/pruning and their guarded writes. `lintai lock` is the explicit approval writer. `build-rules`, `check` and `serve` never regenerate approvals.

The Go configuration loader owns effective policy. Key the optional per-rule tables by semantic rule ID. Missing tables default to severity `error` and options `{}`. An unknown ID is a configuration error. Remove duplicate CLI/host rule-option and per-ID severity overrides. Keep operational flags such as output format and worker count. In the example the schema receives the object containing `pureDir` and `serviceDir`. Bind enforcement-relevant project configuration to the lock using a deterministic digest of effective values, including rule severity/off settings, raw per-rule option values after Go defaults, source selection, bound producer implementation/contract and relevant options, and the chosen suppression policy location. Compute it before running any JavaScript parser. The pack digest covers the parser and its programmatic defaults. Use stable workspace-relative representations for project paths. Exclude presentation options, worker count, physical checkout paths and changing application source bytes. A custom embedding must supply the same effective policy to the same enforcement code. Protect the invocation that selects locked mode and the reviewed lock itself. Application source changes should update facts without requiring renewed rule approval. Document the difference between an approved pack, an approved lint policy and changing analyzed inputs. Identical pack bytes and equivalent policy should verify on any supported platform with the same ABI. Test that claim on native builds where available. Publish no cross-platform build-determinism claim until measured.

A rule owner can build, approve and check a project with these commands.

```sh
lintai build-rules
lintai lock
lintai check --rules-lock lintai-rules.lock.json
```

The middle command belongs to intentional approval. CI runs the first and last commands, chained on success. A missing pack names the build command. A missing or obsolete lock in locked CI is an error. Updating an old-format lock requires an explicit approval command that replaces it atomically after showing the new digest. Never convert an old approval into trust of new bytes without that action. An unbuilt source edit leaves the previously built artifact active in local analysis. Document this prominently.

## 3. Analysis, freshness and compiler input ownership

Make the Go engine the single owner of rule execution, semantic diagnostics, policy and severity. The same configuration composition and analysis paths serve the native CLI, stdin/stdout server and Go embedders. A native `lintai check` performs one forced Full operation. A live or explicit batch request validates current configuration and the last completed publication once per request. On a valid hit, project it. On a miss, analyze and publish atomically. Cancellation, infrastructure failure or incomplete writes must never make partial or stale success reusable. An operation with a rule error may return actionable diagnostics. Its next independent request must have an opportunity to recover. Preserve conflict detection and the distinction between certified metadata hints in Quick mode and content verification in Full mode.

| Identity | What belongs in it |
| --- | --- |
| Rule approval | Whole pack, supported ABI and separately approved effective policy and suppression allowances |
| Compiled plan | Catalog identity, emitted program, typed generated facts, report predicates, expectations and suppression declarations |
| Composed fact snapshot | Catalog identity once and, for each selected producer, namespace, exact requested predicates including arity, input revision and effective scope |
| Publication reuse | Output-affecting request/policy, completed result, pack and other validity evidence, producer eligibility and cancellation/write outcome |
| Source text for a file | Digest of the analyzed text used for that file's coordinates. A workspace fact snapshot alone cannot establish this |

Never assume equal fact snapshot IDs imply equal rule output. Different policies may analyze identical facts. Preserve JSON null, empty array and empty object through all copies used in structured identity. Fix nested typed-nil Go slices/maps in producer configuration detachment. Keep existing suppression normalization where it is a separate public policy. Exact fact demand must drive collection, coverage and reporting. Compile successful plans once per matching key. Allocate writable derived facts per evaluation. Do not cache VM callbacks across operations.

Bind validated immutable producer descriptions to a session once. The TypeScript producer should use the same description it validated when it prepares a generation. Preserve direct-producer argument validation. Configuration changes that alter a producer's description create a new binding. For the Go API choose a fallible session constructor and specify resource ownership. The caller owns supplied producers until construction succeeds. A successful session closes its bound producers once. Preserve serialized checks and safe cancellation. Reduce lifecycle bookkeeping to what active and queued callers require. A close signals the active operation, prevents queued work from publishing, waits without holding a lock needed for completion and then releases resources. For queued callers, closing or cancelling a session must unblock them without starting another analysis. Keep the existing implementation where a shorter replacement would weaken those guarantees.

Use the existing TypeScript observation digest for the producer's input revision. Consolidate parallel compiler maps for stat results, directory reads and realpaths when one captured value can serve both the compiler and evidence generation. Preserve distinctions for absent versus empty directories, failed versus successful realpaths, missing or unreadable files, symlink retargets, and source bytes versus compiler-decoded text. Remove final program file or declaration-map probes only where an equivalent observation was made on the real read, including companion source programs. Keep the narrow tsgo data boundary and sync check. After removing the Node bundler, trace the consumers of the observation JSON decoder and delete its wire-only forms and tests if unused. Keep the semantic digest deterministic if it currently shares encoding with that wire format. Remove the redundant workspace option clones, unused compiler locals, and repeated descriptor fields in a snapshot hash as their owning code changes.

## 4. Host contract

Expose the fixed analysis rules `lintai/error` and `lintai/warning` in each ESLint and Oxlint adapter. The recommended host configuration enables those at error and warning respectively. Go decides whether a semantic diagnostic is an error, warning or disabled. Include the original rule ID and assertion ID in each violation message. Route infrastructure, integrity and rule failures to the error rule. Route unused suppressions at their engine severity. Report pathless workspace failures through the error rule once per bulk operation, including when its first visited file has a source mismatch. A host can explicitly silence an adapter rule. Document the consequence. A per-file host range is valid only for source text verified as described below. The independent authoring preset may contain static checks that still apply to pure authoring. Remove checks solely about the obsolete setup phase. Distinguish intentionally disabled integration from an empty rule pack or failed initialization.

Remove dynamic native rule registration, automatic `lintai rules --json` on plugin creation, per-ID host configuration mirroring, orphan routing, reserved-ID bookkeeping for generated host rules, and restart-to-load-new-IDs logic. A replaced pack can introduce a rule on the next operation, once the corresponding approval has been updated in locked mode. Users configure severity/disablement in `lintai.toml` and rule-specific allowances through lintai's suppression mechanism. ESLint per-rule overrides and disable comments targeting `lintai/<semantic-id>` cease to work. Document the replacement and the difference in granularity. Native host suppressions for the two adapter rules affect every diagnostic in the respective host category. Never promise an equivalent per-file or inline control that lintai does not implement. Read host suppression-overlap configuration at most once per operation, or delete that check if its old semantics apply only to removed names.

Use one host client, one framed request/response mechanism and one projection operation. Change the handshake and use one current protocol version. The selector accepts an ordered array of file names or the explicit value `"all"`. Empty array means workspace problems only. The all-files form returns the analyzed/projectable file groups with stable names. Array responses preserve request order and duplicates, including empty groups. Return the publication's snapshot version, workspace problems and per-file diagnostics and source identity. Validate the number and names of groups at boundaries, and return a normal error for producer/analyzer contract violations. Retain a separate forced operation only for a caller that needs it. Both forced and validated paths call the same engine. Preserve bounded startup, cancellation, orderly shutdown and clear version mismatch errors.

| Operation | Required behavior |
| --- | --- |
| Native CLI | Run a single forced whole-project check. Support human and structured output, usable without a Node executable on PATH after the pack is built. |
| Editor or standalone file callback | Validate one saved-workspace publication for each independent host file analysis. Both severity rules share the response for that file analysis. The next visit may reuse the same host object and must still validate again. |
| Programmatic batch | `withFileBatch(files, callback)` captures once at entry in the same JavaScript process and plugin instance as the host callbacks. An external executable uses invocation mode. All declared files project from that publication until the callback settles. Expose workspace problems even for an empty list. Reject undeclared files. Overlapping and nested calls retain their own publications. Close the operation on failure as well as success. |
| Raw host CLI lint run | Provide an explicit invocation-scoped adapter configuration, e.g. `createLintaiPlugin({ operation: "invocation" })`. It obtains one all-files publication for this invocation and projects every callback locally. Give copyable ESLint and Oxlint CLI configs/commands for it. For example, a shared project config can select invocation only when its bulk script sets `LINTAI_HOST_OPERATION=invocation`. The editor loads that same config with the default live setting. The default long-lived editor configuration uses `operation: "live"`. Embedders reusing a host process across lint runs create a fresh invocation instance or use the batch callback. |

For the supported bulk commands, disable a host file-result cache that can skip a callback after an imported file or policy changes. Use one JS plugin instance per workspace and invocation. If an ESLint worker setting constructs separate instances, document and use its single-worker setting in the supported bulk command. Keep Oxlint native worker parallelism when its JS plugin shares one instance. Verify the invocation count through the installed hosts. This design needs no cross-process cache or broker.

Use the same framed Go server for host requests in all three host lifetimes. An invocation may dispose of the child as soon as its complete snapshot is in hand. Remove the separate synchronous whole-stdout JSON implementation and its fallback state. A pack with a realistic multi-megabyte result must return all findings through installed host adapters. A transport failure produces an actionable operation error, closes the failed transport and permits a fresh connection on a subsequent independent live operation. Never serve cached success as recovery. Establish lifetime explicitly in the factory/config and callback. Avoid argv detection, timers that guess a lint pass, file-count heuristics or process-wide cache of responses. A workspace problem appears once per invocation/batch, remains available to the callback, and is available on a later independent editor operation. Document the empty-host-run case. Native CI must expose workspace failures even when a host visits zero files.

Derive each projected file's source identity from the immutable text actually used to produce its locations. Define it as SHA-256 over the UTF-8 encoding of that decoded logical text with one leading BOM removed. Preserve line endings and all other characters. The adapter applies the same transform to the host's unmodified source text, using the host BOM flag to reconstruct the leading BOM when its API has already stripped one. A genuine second BOM is part of the digest. Verify the representative encodings against the installed hosts. Projected results must not require rereading the current disk. If the host text matches, show the results even if disk has since moved on. If it differs, or if there are located findings whose source identity cannot be established, suppress those ranges and emit one clear rerun/save notice for the file. Report a mismatch through `lintai/error` once for that file analysis. Host text mismatch must not hide pathless workspace errors. A lookup outside the captured file set projects no findings. A file added after capture joins on the next operation. These cases issue no per-file fallback request. Document this frozen file-set behavior. For external producers with locations, reuse an already captured source identity or let the generation supply the optional per-file identity. Reuse that evidence throughout. Conflicting source identities for one group must never produce apparently verified ranges.

Normalize workspace-owned file names for lookup. An absolute path inside the root may match its workspace-relative form. Keep an outside absolute path distinct from a same-spelled relative name, including on different Windows volumes. Preserve request spelling in returned arrays. Use the same file mapping for the diagnostics and their source identity. Keep path normalization separate from content equivalence.

Each active plugin instance owns its client and disposes it idempotently. If both host rules are off through the documented disabled integration, no child is required. Oxlint can have Linux process-start limitations after plugin loading. Prove early startup of the real server from the configured active plugin with the packed Linux CLI and language-server fixture before deleting the existing spawner. If the real host needs a helper, keep only the minimum early-spawn path and share the ordinary framed client. Avoid a subprocess at module import for an authoring-only or explicitly disabled setup. Show results for actual installed packages, including child shutdown. Terminate the real Go child after the packed Oxlint language server has loaded and exercise recovery on a subsequent operation in the same host. An early successful launch alone does not justify deleting the helper.

## 5. Implementation order and acceptance

Use three reviewable commits or groups on the single third branch. Keep any parent correction already present. Reuse its regression. Each group should delete superseded code in the same group as the replacement.

1. **Rule build and execution.** Implement the pack, explicit compiler, pure config and SDK, approval and suppression contract. Port real rules and CLI examples. Remove both preparation/bundling scripts and packaged copies, runtime resolver capture, the setup sandbox and flags, obsolete dependencies and package assets. Check a packed install and an executable with Node absent from PATH.
2. **Engine and inputs.** Bind producer descriptions, preserve complete plan reuse and exact demand, repair structured identity and path grouping, expose captured source identity, and simplify capture, lifecycle and publication where the old state is redundant. Test Go embedders and update the consumer module. Keep TypeScript semantic extraction and public facts unless a named correctness case requires a change.
3. **Hosts and removal.** Ship fixed severity rules, explicit operations and one protocol. Convert packed examples, benchmarks, docs, client and host tests. Remove obsolete one-shot/fallback, process heuristics, dynamic discovery, fake child-process implementations and test cases that exercise only removed features. Explain how to run bulk lint and how editors refresh after editing a rule.

Use the following cases to decide which tests to retain.

| Area | Evidence required |
| --- | --- |
| Build and trust | Same inputs at different checkout roots produce the same pack on the tested platform. Static JSON or dependency edit changes behavior and approved bytes when emitted code changes. A failed build preserves the old complete pack and CI stops. Missing, altered, added, removed or unsupported entries, changed effective enforcement policy and raised suppression allowances fail enforcement before rule evaluation. New approval is always explicit. |
| Rule and engine | One representative mixed-failure golden for ordering and rule isolation, one real changed-facts/unchanged-facts case for diagnostics and compilation reuse, one real source-selection change, and cheap Go producer cases for null/empty, demand, scope and opaque revisions. Capture → edit → project must retain the original source identity. Cancellation/failure never publishes partial success. Cover concurrent close with the existing race tests. |
| Hosts | One real edit during a batch in each direction. Verify the original text, newly saved text and next independent operation. Check both severities, original IDs, replacement-pack rule addition without restart, path collision, duplicates, empty batch and failure recovery. | Packaging | Existing full Go tests and relevant race, package build/test, packed CLI, ESLint, Oxlint and language-server smokes, consumer module, compiler sync and examples pass on the landed tree.
