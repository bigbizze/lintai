# Future work: multi-config analysis

- Ordinary analysis intentionally has one owner per selected file. There is no owner override or ordinary multi-context mode.
- Automatic declaration maps use parser recovery. Configured correspondence has its own planned compiler contexts.
- A future experiment may sample real multi-project repositories, count known root overlaps, name the actual configs compared, and compare normalized calls, signatures, and exports for shared files.
- Report denominators and separate semantic differences from identity or ordering differences. Known inventory overlap does not enumerate every possible config.
- No all-context engine, new conflict API, equivalence cache, or performance implementation is included now.
